# SlingTab

Draw a circle over a link — with the mouse, or with your hand in the air — and
the page is punctured inside the disc. A ring of sparks ignites along the traced
path, the destination shows through the hole, and the viewport dives into it. A
matching animation finishes on the arriving page.

Chrome MV3 · TypeScript · WebGL2 with a Canvas2D fallback.

```bash
npm install
npm run build      # tsc --noEmit && vite build  ->  dist/
npm test           # vitest
npm run dev        # @crxjs HMR
npm run tune       # localhost:5180 — live rim tuner
npm run icons      # regenerate public/icons/*.png
```

Then `chrome://extensions` → Developer mode → **Load unpacked** → `dist/`.

## Triggers

| | |
|---|---|
| **Right mouse button** | Hold it and draw. A right-click that does not become a circle still opens the context menu. |
| **Hold Alt** | No buttons. Better on a trackpad. |
| **Hand in the air** | Raise index and middle finger and draw a circle at the webcam. |

## Privacy

Everything happens on the machine.

- The webcam feed is read frame by frame and discarded. Nothing is recorded,
  uploaded or stored, and the camera runs only while the hand trigger is
  selected. The hand model is bundled and works offline.
- MediaPipe's own usage telemetry is rewritten to a dead path at build time, and
  **the build fails** if that endpoint ever stops being found — so a dependency
  upgrade cannot quietly reintroduce it.
- The page snapshot behind the lens is `captureVisibleTab` on your own active
  tab. It never leaves the machine and is dropped when the portal closes.
- Preview fetches for the destination use `credentials: "omit"`, so nothing
  personalised is pulled into a preview.

The one thing worth knowing: circling a link fetches that URL before you commit,
to build the preview. The site learns you looked, the way a hover-prefetch would.

## Where the documentation lives

**[HANDOFF.md](HANDOFF.md) is the reference**, and the only one kept current:
architecture, the three flows, verified platform constraints, the bug ledger
with root causes, tuning constants, and the open items.

This file is deliberately short. An earlier version of it restated HANDOFF.md's
technical content and then drifted — by the end it documented a DOM-transform
dive that had been deleted (bug 3), an iframe timeout that had changed, and a
`captureVisibleTab` that it claimed was unused while the lens depended on it.
Two documents describing one architecture is a defect with a delay fuse. If you
are tempted to explain a mechanism here, explain it in HANDOFF.md instead.

## Naming

The extension is **SlingTab**. No Marvel or Doctor Strange names, marks,
character likenesses or film stills appear anywhere in the repo. The rune bands
are procedural; the icons are generated by `tools/make-icons.mjs` with a
hand-rolled PNG encoder over `node:zlib`.
